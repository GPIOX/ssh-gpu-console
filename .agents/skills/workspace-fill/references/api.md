# Workspace API cheat sheet (local control plane, http://127.0.0.1:8420/api/v1)

All bodies are JSON; unknown fields are rejected (`extra="forbid"`). Writes go
to `backend/data/workspace.json` (explicit CRUD only); inspections are RAM-only.

## Servers (registry)

```bash
curl -s :8420/api/v1/servers | jq 'map({display_name, server_id, ssh_host, enabled})'
```

Server ids are generated by the registry; everything in /workspace speaks
`server_id`, so map `display_name → server_id` first.

## Projects

```bash
# list
curl -s :8420/api/v1/workspace/projects
# create
curl -s -X POST :8420/api/v1/workspace/projects -H 'Content-Type: application/json' \
  -d '{"name": "My-Project", "description": "…", "tags": ["segmentation"]}'
# attach artifacts (also accepts name/description/tags)
curl -s -X PATCH :8420/api/v1/workspace/projects/<project_id> \
  -H 'Content-Type: application/json' -d '{"artifact_ids": ["<a1>", "<a2>"]}'
# default transfer excludes (rsync/fnmatch patterns; relay skips matching
# entry names, rsync gets --exclude=arg; union across referencing projects)
curl -s -X PATCH :8420/api/v1/workspace/projects/<project_id> \
  -H 'Content-Type: application/json' \
  -d '{"transfer_excludes": ["dataset", "checkpoints", ".git", "__pycache__"]}'
```

- `artifact_ids` is the stored, explicit association (validated server-side;
  unknown ids → 409).
- `launch_config_ids` is DERIVED at read time from launch configs whose
  `project_id` matches — never settable, never stored.
- `transfer_excludes` (≤32 single-line patterns) is the project's DEFAULT
  exclusion list; blank entries and duplicates are rejected/collapsed.

## Artifacts

```bash
curl -s -X POST :8420/api/v1/workspace/artifacts -H 'Content-Type: application/json' \
  -d '{"kind": "dataset", "name": "D1", "description": "primary dataset (~12 GB)"}'
```

- `kind`: `code | dataset | model`.
- `version` (≤64 chars) distinguishes run variants of the same model name.
- `immutable`: defaults to `true` for datasets/models, `false` for code.
- `name` ≤120, `description` ≤600.

## Placements (declarations only)

```bash
# create
curl -s -X POST :8420/api/v1/workspace/placements -H 'Content-Type: application/json' \
  -d '{"artifact_id": "<id>", "server_id": "<id>", "remote_path": "/home/demo/projects/app/data/D1"}'
# inspect (RAM-only): stat the real path + count top-level files
curl -s -X POST :8420/api/v1/workspace/placements/<placement_id>/inspect
```

- `remote_path` ≤512 chars, stored verbatim (strip'd). Use absolute or `~`-based
  paths — relative paths would resolve against the SSH session cwd at inspect
  time.
- Duplicate (artifact, server, path) triples → 409.
- Inspect states: `declared` (not yet checked), `verified`, `missing`,
  `unavailable` (server offline/disabled — never a 404).

## Server roots (per server)

```bash
curl -s -X PUT :8420/api/v1/workspace/server-roots/<server_id> -H 'Content-Type: application/json' \
  -d '{"project_root": "/home/demo/projects", "dataset_root": "/home/demo/data",
       "model_root": "/home/demo/runs", "output_root": "/home/demo/output"}'
```

- Declarations only (≤512 chars each); saving does not create directories
  remotely.
- Used by the New-Transfer dialog to prefill the target path:
  `<root of kind>/<name>[:<version>]`. Set them on the TARGET server before
  syncing.

## Launch configs

```bash
curl -s -X POST :8420/api/v1/workspace/launch-configs -H 'Content-Type: application/json' \
  -d '{
    "project_id": "<id>", "name": "Ablation D1 · variant1",
    "working_dir": "/home/demo/projects/app",
    "program": "train_d1_variant.py",
    "args": ["--ablation", "variant1", "--dataset_path", "./data/D1"],
    "environment": "env-name", "required_artifact_ids": ["<code>", "<d1>"],
    "gpu_count": 1
  }'
```

- Shell metacharacters are rejected in `program`/`working_dir` (validation in
  `app/models/workspace.py`): no `; & | $ ( ) { } [ ] * ? ~ " '` or newlines —
  split shell syntax into structured `args`.
- `args` ≤64 tokens; `environment` ≤120 chars (conda env name); `gpu_count`
  1–64; `env_vars` ≤32 string→string pairs.
- Copy real flags from the user's actual training scripts (read-only grep) —
  never invent them.

## Transfers (MVP)

```bash
# plan (dry-run: strategy decision + size)
curl -s -X POST :8420/api/v1/transfers/plan -H 'Content-Type: application/json' \
  -d '{"artifact_id": "<id>", "source_placement_id": "<id>", "target_server_id": "<id>",
       "target_path": "/home/demo/data/D1", "strategy": "auto"}'
# create (202, job runs in background; RAM-only state)
curl -s -X POST :8420/api/v1/transfers -d '…same body…'
# list / detail / cancel / retry
curl -s :8420/api/v1/transfers ; curl -s :8420/api/v1/transfers/<job_id>
curl -s -X POST :8420/api/v1/transfers/<job_id>/cancel ; curl -s -X POST :8420/api/v1/transfers/<job_id>/retry
```

Fixed rsync flags (`-a -r -t -p -o -g --partial --partial-dir=.sgc-rsync-partial
--info=progress2`), never `--delete`/`--append`; local relay is chunked RAM
(4 MiB default) with no local staging file. Target placements are recorded
automatically, once, after a successful transfer.
